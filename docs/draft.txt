                           The RecipeJSON Format (Project Gourmet Variant)

Abstract

   RecipeJSON is a recipe data interchange format based on JavaScript
   Object Notation (JSON).  It defines a type of JSON objects and
   the manner in which they are combined to represent data about
   recipes features, their properties, and their spatial extents.

Status of This Memo

   This is currently in the experimental stage and very much subject to change.
   The first draft was created from the 2017-07-20 to the 2017-07-22 at the "Code Kombüse" Hackathon and
   is my first formal definition, so don't hit me for it.
   The second draft was created on 2017-08-11.
   The third draft was created on 2026-01-17.
   The variant for Project Gourmet was created on 2026-01-19.

===============================================================================================

1.0.0 Recipe envelope definition

    The base level of a RecipeJSON has to contain the following fields:

    `version`, `variant`, `title`, `id`, `language`, `creationDate`, `servings`, `recipes`

    it may also contain the following fields:

    `subtitle`, `source`, `author`, `images`, `audio`, `links`, `tags`

1.0.1 Version

    A Recipe envelope has to contain a field `version` as number. This draft just defines version 1,
    more may be defined in the future, and may not be compatible to this version.

1.0.2 Variant

    A Recipe envelope has to contain a field `variant` as string. This must always be set to "gourmet".

1.0.3 Title

    A Recipe envelope has to contain a field `title` as string. This should just be the title of the whole recipe.

1.0.4 ID

    A Recipe envelope has to contain a field `id` as string.
    The ID is used to uniquely identify the recipe. This ID should not change for language variations of a recipe.

1.0.5 Language

    A Recipe envelope has to contain a field `language` as string.
    This is should be the language of the recipe, and contain any IETF BCP 47 Code.

1.0.6 Creation Date

    A Recipe envelope has to contain a field `creationDate` as string.
    This is should be the creation date and time as ISO 8601 date formatted as YYYY-MM-DDThh:mm:ssTZD.

1.0.7 Servings

    A Recipe envelope has to contain a field `servings` as object.
    This itself has to contain two fields:

    `type`, `count`

    `type` may be one of two values:

        `person` marking it as serving number of persons or
        `item` marking it as producing number of items

    `count` has to be a number and identifies the number of persons or servings of the recipe

1.0.8 Recipes

    A Recipe envelope has to contain a field `recipes` containing a list of Recipe objects.
    The Recipe object is defined in 1.2.0.

1.0.9 Subtitle

    A Recipe envelope may contain a field `subtitle` as string.
    The subtitle should describe the recipe in more detail than the title.

1.0.10 Source

    A Recipe envelope may contain a field `source` as string.
    The source has to contain a URL to the source.

1.0.11 Author

    A Recipe envelope may contain a field `author` as string.
    The author may contain an email address or username.

1.0.12 Images

    A Recipe envelope may contain a field `images` as a list of strings.
    The images have to be URLs or paths to the images on the local filesystem and should display the full recipe with all subrecipes.
    Local paths may be relative or absolute.

1.0.13 Audio

    A Recipe envelope may contain a field `audio` as a string.
    The audio has to be a URL or a path to the audio on the local filesystem and should be a verbal description of the recipe.
    Local paths may be relative or absolute.

1.0.14 Links

    A Recipe envelope may contain a field `links` as a list of strings.
    The links should be to websites containing relevant infomation for this recipe.

1.0.15 Tags

    A Recipe envelope may contain a field `tags` as a list of strings.
    The tags should describe the recipe and may be used for search.

===============================================================================================

1.2.0 Recipe object definition

    The Recipe objects of a RecipeJSON have to contain the following fields:

    `ingredients`, `directions`

    it may also contain the following fields:

    `utensils`, `title`, `subtitle`, `images`, `audio`, `links`, `tags`

    The title is not mandatory, but recipes containing multiple subrecipes should contain a title.

1.2.1 Ingredients

    A Recipe object has to contain a field `ingredients` containing a list of Ingredient objects.
    The Ingredient object is defined in 1.3.0.

1.2.2 Directions

    A Recipe object has to contain a field `directions` containing a list of Direction objects.
    The Direction object is defined in 1.6.0.

1.2.3 Utensils

    A Utensils object may contain a field `utensils` containing a list of Utensil objects.
    The Utensil object is defined in 1.4.0.

1.2.4 Title

    A Recipe object may to contain a field `title` as string.
    This is should just be the title of the subrecipe.

1.2.5 Subtitle

    A Recipe object may contain a field `subtitle` as string.
    The subtitle should describe the recipe in more detail than the title.

1.2.6 Images

    A Recipe object may contain a field `images` as a list of strings.
    The images have to be URLs or paths to the images on the local filesystem and should display just the subrecipe.
    Local paths may be relative or absolute.

1.2.7 Audio

    A Recipe object may contain a field `audio` as a string.
    The audio has to be a URL or a path to the audio on the local filesystem and should be a verbal description of the subrecipe.
    Local paths may be relative or absolute.

1.2.8 Links

    A Recipe object may contain a field `links` as a list of strings.
    The links should be to websites containing relevant infomation for this subrecipe.

1.2.9 Tags

    A Recipe object may contain a field `tags` as a list of strings.
    The tags should describe the recipe and may be used for search.

===============================================================================================

1.3.0 Ingredient object definition

    The Ingredient objects of a RecipeJSON have to contain the following fields:

    `unit`, `id`, `type`

    it may also contain the following fields:

    `amount`, `attributes`, `substitutes`

1.3.1 Unit

    An Ingredient object has to contain a field `unit` as string.
    The unit should contain a string describing the unit. Further definition needed for better automation.

1.3.2 ID

    An Ingredient object has to contain a field `id` as string.
    The ID is used to link the ingredient to an external ingredient JSON, which contains required data such as name, description, and pictures.

1.3.3 Type

    An Ingredient object has to contain a field `type` as string.
    The type may be either "required" or "recommended", depending on what the recipe needs.

1.3.4 Amount

    An Ingredient object may contain a field `amount` as string.
    The amount is a number used in conjunction with unit to describe how much of the ingredient should be used.

1.3.5 Attributes

    An Ingredient object may contain a field `attributes` as a list of strings.
    The Attributes should be used to describe the ingredient further.

1.3.6 Substitutes

    An Ingredient object may contain a field `substitutes` containing a list of Substitute objects.
    The Substitute object is defined in 1.5.0.

===============================================================================================

1.4.0 Utensil object definition

    The Utensil objects of a RecipeJSON have to contain the following fields:

    `id`, `type`

    it may also contain the following fields:

    `amount`, `substitutes`

1.4.1 ID

    A Utensil object has to contain a field `id` as string.
    The ID is used to link the utensil to an external utensil JSON, which contains required data such as name, description, and pictures.

1.4.2 Type

    A Utensil object has to contain a field `type` as string.
    The type may be either "required" or "recommended", depending on what the recipe needs.

1.4.3 Amount

    A Utensil object may contain a field `amount` as string.
    The amount is a number to describe how many of the utensil should be used.

1.4.4 Substitutes

    A Utensil object may contain a field `substitutes` containing a list of Substitute objects.
    The Substitute object is defined in 1.5.0.

===============================================================================================

1.5.0 Substitute object definition

    The Substitute objects of a RecipeJSON have to contain the following fields:

    `name`, `type`

    it may also contain the following fields:

    `unit`, `amount`, `attributes`

1.5.1 Name

    A Substitute object has to contain a field `name` as string.
    The name is used to identify the ingredient or utensil in the directions.

1.5.2 Type

    A Substitute object has to contain a field `type` as string.
    The type can be either "required" or "recommended", depending on what the recipe needs.

1.5.3 Unit

    A Substitute object may contain a field `unit` as string.
    The unit (which can only be used with Ingredient substitutes) should contain a string describing the unit. Further definition needed for better automation.

1.5.4 Amount

    A Substitute object may contain a field `amount` as string.
    The amount (which can only be used with Utensil substitutes) is a number to describe the quantity of the utensil that should be used.

1.5.5 Attributes

    A Substitute object may contain a field `attributes` as a list of strings.
    The Attributes (which can only be used with Ingredient substitutes) should be used to describe the ingredient further.

===============================================================================================

1.6.0 Direction object definition

    The Direction objects of a RecipeJSON have to contain the following fields:

    `type`, `text`

    it may also contain the following fields:

    `duration`, `images`, `audio`, `ingredients`, `result`

1.6.1 Type

    A Direction object has to contain a field `type` as string.
    The type can be either `preparation` marking the direction step as a preparation step
    or `cooking` marking it a step cooking something.

1.6.2 Text

    A Direction object has to contain a field `text` as string.
    The text should discribe the actions that have to be taken in this direction.

1.6.3 Duration

    A Direction object may contain a field `duration` as string.
    The duration should be a ISO 8601 duration string.

1.6.4 Images

    A Direction object may contain a field `images` as a list of strings.
    The images have to be URLs or paths to the images on the local filesystem and should display just the direction.
    Local paths may be relative or absolute.

1.6.5 Audio

    A Direction object may contain a field `audio` as a string.
    The audio has to be a URL or a path to the audio on the local filesystem and should be a verbal read of the `text` string.
    Local paths may be relative or absolute.

1.6.6 Ingredients

    A Direction object may contain a field `ingredients` as a list of strings.
    The strings should reference either on of the ingredients or a result from a previous direction step.

1.6.7 Result

    A Direction object may contain a field `result` as a list of strings.
    The results may be used in the ingredients for directions, or can be omitted.

Changes:

    Second Draft 2017-08-11

    - `result` in the Direction object is not a simple string anymore but a list of strings instead.
    - A Direction object must contain a new field `type` that can either have the value `preparation` or the value `cooking` marking it either a manual preparation step or a cooking step.

    Third Draft 2026-01-17
    - A Recipe object may contain a new field `utensils` that contains a list of required or recommended cookware for the recipe.
    - An Ingredient object has to contain a new field `type` that contains a string noting whether the ingredient is "recommended" or "required".
    - A Recipe envelope, Recipe object, and Direction may contain a new field `audio` for embedding an audio file containing verbal information about the recipe or direction.
    - The Ingredient and Utensil objects may contain a new field `substitutes` that contains a list of alternatives for the Ingredient or Utensil.
    - `images` in the Recipe envelope, Recipe object, and Direction object can now optionally include paths to image files on the local filesystem instead of only URLs. Local paths may be relative or absolute.
    - `language` in the recipe envelope now uses IETF BCP 47 language codes instead of ISO 639-1. This allows for specification of regional language variations (e.g. "en-US"), useful in cases where a component's name differs by region.
    - Some minor grammar corrections have been applied throughout.

    Project Gourmet Variant (rolling release)
    - Added unique identifiers for recipes. Possibly to be replaced with UUIDs in the future.
    - Replaced ingredient and utensil names with unique identifiers.
    - Removed sample recipe until an English sample recipe can be created.
